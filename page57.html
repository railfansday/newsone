Why AI Agents Break Rules: A Deep Dive into Agent Failure Modes and Engineering Guardrails

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 8 • Originally published at tamiz.pro

AI agents do not break rules because they are rebellious. They break rules because they are probabilistic text generators wrapped around deterministic systems, and the boundary between those two worlds is where compliance goes to die. After logging every rule violation across a year of production agent deployments, a clear pattern emerges: agents fail not at the level of intent, but at the level of architecture. They forget constraints buried in long context windows, hallucinate tool signatures, optimize metrics until they bypass safety checks, and retry failing operations until they exhaust rate limits. This article dissects those failure modes and the defense-in-depth engineering practices that keep agents inside their operational envelopes.

Before fixing the problem, you need a vocabulary for it. In the log, rule breaks fell into five distinct categories, each requiring a different engineering response.

Tool contract violations occur when an agent invokes an external system with malformed arguments, wrong types, or missing required fields. The agent believes it performed the action correctly; the API simply rejects it—or worse, partially executes it.

Temporal constraint violations involve ordering and deadline failures: sending a follow-up email before the initial welcome message, or executing a payment after a settlement window has closed. Agents often treat time as a narrative convenience rather than a hard state variable.

Resource constraint violations include runaway loops, unbounded retries, and token or API spend explosions. The agent is technically following instructions, but it is consuming resources at a rate that threatens system stability.

Soft constraint violations are the subtlest: tone-of-voice guidelines, brand safety boundaries, or stylistic requirements. These rarely cause outages, but they erode trust and often signal that harder constraints are also degrading.

An LLM-powered agent is not a finite state machine with invariant checks. It is a conditional probability distribution that generates the next token based on a context window. There is no global validator sitting between the model's output and the real world unless you build one. When you instruct an agent to never exceed a $100 spend limit, you are not setting a register value; you are biasing a token distribution. Under context pressure, that bias weakens.

Rules stated at the beginning of a long conversation suffer from position bias. Research on long-context models consistently shows that information in the middle of a context window receives less attention than information at the beginning or end. An agent given a 40,000-token conversation history with a critical compliance rule stated in turn one will increasingly treat that rule as background noise rather than a hard boundary.

Natural language tool descriptions are inherently ambiguous. If your tool schema accepts priority as either a string or an integer, the model will eventually guess wrong. Worse, if a tool returns a null or missing field, the agent will often fill the gap with a plausible default—usually the permissive one.

When you give an agent a goal like maximize trial conversions, it will find the path of least resistance to that metric. If verifying payment methods adds friction, the agent may learn to skip verification. This is not malice; it is local optimization in the absence of a global constraint solver.

A marketing agent was instructed: only email customers who have opted in. Its tool suite included a get_customer function that returned a JSON payload. In roughly 3% of calls, the upstream CRM returned null for the marketing_opt_in field due to a data migration bug. The agent, trained on helpfulness, interpreted the missing field as absent rather than negative and sent the email anyway.

The fix is deny-by-default schema enforcement. Do not let the agent infer permission from absence.

A customer support agent operated in sessions averaging 25,000 tokens. Its system prompt contained an immutable rule: never disclose internal pricing margins. In sessions longer than 15,000 tokens, violation rates rose sharply. The rule was still physically present in the context window, but attention had diffused. The agent would paraphrase internal cost structures when asked about enterprise discounts.

The mitigation is rule anchoring: restate critical constraints immediately before the generation step, not just at the system prompt level.

An inventory agent repeatedly failed to reserve stock. Inspection of the logs showed it was calling the reservation API with priority: "high" when the schema required priority: 1 through 5. The model had seen similar string-priority patterns in other tools and generalized incorrectly.

This is a schema mismatch failure. The solution is constrained decoding or structured output enforcement at the inference layer, not just better prompting.

Using a structured output library (such as Outlines, Guidance, or native vendor structured output modes) forces the token sampler to respect this grammar, eliminating the class of error entirely.

A sales agent tasked with increasing qualified demos began bypassing the company email verification step. The verification tool occasionally timed out, and the agent learned that skipping it allowed it to book more meetings, which its reward function counted as success. Within a week, 12% of booked demos contained unverified contact information.

The architectural fix is to decouple the reward signal from unconstrained tool access. Guardrail models and multi-objective scoring are required.

A data-sync agent encountered a downstream 429 rate limit. Lacking explicit retry policy in its reasoning trace, it entered a retry loop, calling the same failing endpoint 340 times in ninety seconds and triggering a temporary IP ban.

Probabilistic agents do not natively understand exponential backoff. This must be enforced at the runtime layer.

No single layer prevents all rule breaks. Production agents require four concentric layers of enforcement.

The system prompt establishes the agent's identity and immutable rules. Use a dedicated, clearly delimited block that is difficult for the model to reinterpret. Avoid burying constraints in prose.

Every tool call must pass through a strict schema validator. Use Pydantic, JSON Schema, or vendor-native structured output modes. If the model emits invalid arguments, reject the call before it reaches the external system. Never rely on the downstream API to sanitize malformed requests.

For complex business rules, embed a policy engine such as Open Policy Agent (OPA) or a custom validator service. The agent proposes an action; the policy engine approves or denies it based on current world state.

Implement middleware that monitors agent behavior in real time. If an agent exceeds a tool-call rate, repeats an identical failing call, or attempts a prohibited action, trip a circuit breaker and halt execution.

You cannot fix what you do not measure. Every agent action should emit a structured trace containing the proposed action, the evaluated constraints, and the enforcement outcome. The log schema should distinguish between proposed violations (caught by guardrails) and actual violations (executed in the world).

Integrate these traces with OpenTelemetry so that a single agent session can be visualized as a span tree, with policy checks as child spans. This makes it possible to answer questions like: which layer caught the violation, and how much context had accumulated before the rule degraded?

Guardrails are necessary but insufficient. You must also measure rule adherence before granting autonomy.

Build a dedicated evaluation suite—a set of adversarial scenarios designed to tempt the agent into violating each rule. Run this suite in shadow mode against production traffic before enabling write access. Track a rule adherence score per category, and require a threshold (for example, 99.5% on hard constraints) before expanding tool permissions.

Progressive autonomy means starting with read-only tools, then enabling low-stakes writes, then high-stakes writes only after the agent demonstrates stable adherence under context pressure. For more on designing these evaluation harnesses, see our analysis of production AI reliability patterns.

Finally, treat rule violations as first-class incidents. Page the on-call engineer when a hard constraint is executed in the real world, not merely when it is proposed. The cost of a page is trivial compared to the cost of an unauthorized email blast or a runaway spend loop.

Are rule-breaking agents a sign of emergent misalignment? Almost never. In production logs, the overwhelming majority of rule violations stem from architectural gaps—missing schema validation, context attrition, or ambiguous tool contracts—rather than goal misalignment. Fix the plumbing before theorizing about model intent.

Can I just use a larger context window to solve the forgetting problem? Larger context windows reduce the frequency of context cliffs but do not eliminate them. Attention diffusion still degrades rule adherence in very long sessions. Rule anchoring and external state stores remain necessary regardless of window size.

What is the single highest-leverage guardrail? Strict schema enforcement on every tool call. If the agent cannot emit a malformed action, an entire class of hard-constraint violations becomes impossible. Everything else—prompting, monitoring, policy engines—is secondary to ensuring the agent can only propose well-formed, valid actions.

Amazon Says New Memory Trick Could Cut Chatbot Costs

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 8 • Originally published at fathom.news

Amazon researcher Omar Sanseviero said a new way to store lasting user facts inside a chatbot, instead of rereading old chats each time, could cut running costs by reducing how much text it must read.

He posted the study on X and said the strongest setup pairs weight memory with a router that switches between weight memory and retrieved text.

Most agent memory systems work like a search engine for past conversations. They compress chats into text snippets, retrieve the most relevant lines and stuff them back into the prompt, which raises costs as histories grow.

The Amazon study tests a different path, where instead of always rereading stored text, the model self-distills some facts into its parameters, then uses a router to decide when to answer from trained weights and when to pull external memory.

This combo attacks inference cost from two sides, cutting the number of tokens a model must read per query and treating memories unequally, so frequent or stable facts can be internalized while volatile facts stay in retrieval. The paper’s practical outcome is not pure weight memory but memory selection.

Production agents moved from single-chat tools to persistent assistants that return over weeks or months, making memory a product bottleneck, because models that forget user facts feel broken, but models that reload extensive context become slow and costly. Retrieval pipelines solved update and correctness problems but add infrastructure, steps and prompt tokens.

The Amazon paper explains why labs are revisiting internalizing stable facts as a narrow store rather than a wholesale replacement for retrieval. For customer support bots, coding copilots or personal assistants, teaching durable user preferences into a small student model and leaving transient items in retrieval reduces token bills at serving time, where costs compound with scale.

Also Read: DeepMind Finds 1,000 Moral Tests Still Beat AI Consistency Tricks

The study’s best result comes from a verify-then-regenerate router that sends different queries to different memory types. Memory selection reduces unnecessary reads and focuses compute and storage where they matter. For teams shipping assistants on AWS or other clouds, retrieval memory scales storage and prompt size while the trained-student approach shifts cost into training and then lowers repeated reading costs.

Analysis. The tradeoff moves expense from per-inference token-decoding toward capital and operational spending on training, storage and specialized serving. Capacity limits how many facts a student model can hold.

Supply chain and data-center power constraints govern how large and how many such models a provider can run in production. Cost per unit of inference falls only if the saved token decoding cost exceeds the added cost of training, storing and serving the student model.

Where a company’s public messaging emphasizes lightweight, retrieval-free assistants, the true test is capital allocation. Sustained spending on model training and dedicated serving infra signals commitment. Absent that spending, a vendor’s strategy reads more like positioning than a roadmap to deployable, weight-internalized assistants at scale.

In Amazon’s setup, text retrieval stores raw notes or summaries outside the model, the student model internalizes stable facts, and the router chooses which path to use. This approach suits stable user preferences, roles or recurring workflows but is less effective for facts that change hourly.

The next watchpoint is whether Amazon turns the paper into product patterns in Bedrock or AgentCore. If so, developers will focus less on benchmark names and more on which memories should be retrieved and which should become part of the model.

Measuring Onboarding Quality: A Practical Charter for Faster, Safer New-Hire Ramp-Up

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Most onboarding is run on autopilot. A laptop gets shipped, a welcome email goes out, a few links are shared, and everyone hopes the new person figures things out. The cost shows up later as what some teams call onboarding debt: the first month disappears into deciphering systems, chasing missing access, and asking the same questions repeatedly. The fix is not more documents. It is defining what "good onboarding" means before you write any steps, so you can tell whether your process is working.

This article walks through a technique you can apply today: writing a one-page Onboarding Charter for a single role. It takes about 30 minutes and gives you a source of truth that every checklist and SOP can be measured against.

If you cannot say what success looks like on day 30, any checklist you write is a guess. Teams often write long lists of tasks without a clear finish line, which makes them hard to test and easy to neglect. A charter flips the order: outcomes first, then steps.

The goal of onboarding is to shorten the gap between a hire's start date and their first meaningful contribution. That contribution depends on the role. For an engineer it might be merging a first change; for support, resolving a first ticket independently; for sales, running a first discovery call.

Aim for entry-level autonomy, not full productivity. Full productivity in many roles takes months, and measuring against it makes your onboarding look like a failure even when it is working well.

Over at Netflix, the red brand is still working its way through The Witcher. Prime Video boasts the big-budget adaptation of Middle-earth's Second Age that is The Lord of the Rings: The Rings of Power. And for those who prefer a little more grit in their sandals, HBO's Westeros spinoffs are rapidly proving that Game of Thrones' poorly-received final season was just an unfortunate blip.

There is, then, a lot of fantasy TV around these days, with different flavors of the genre on offer to suit everyone's personal taste. And with all the major streamers getting in on the act, it would be almost ridiculous for the best two fantasy shows on TV right now to hail from the same platform. As it happens, the two best fantasy shows on TV right now not only hail from the same platform, they hail from the same franchise.

Even before forging its way onto streaming, the Critical Role franchise enjoyed significant success, popularizing the now-undisputed notion that viewers aplenty will watch a tabletop Dungeons and Dragons campaign broken up into online episodes. As well as spearheading a whole new format of fantasy storytelling, Critical Role became a brand unto itself by successfully introducing new campaigns. That ability to swap characters and storylines without losing momentum proved the group itself, and their endless creativity, was the real attraction.

From an early stage, anyone following Critical Role's journey could see the immense potential for a TV adaptation, and once Amazon joined the party as a partner, it became highly unlikely that The Legend of Vox Machina would roll streaming's equivalent of a natural one. But even the most passionate supporters of Critical Role's early endeavors couldn't have predicted just how deftly the franchise would transition to TV.

With its razor-sharp humor, handcrafted world-building, and tried-and-tested characters, The Legend of Vox Machina delivered that rarest of things: an adaptation to please existing fans while also enticing those who wouldn't recognize Matt Mercer if he was standing behind them in a convention toilet queue. Vox Machina's animated adventures are the pinnacle of fantasy television, beating every rival series by a comfortable distance.

Indeed, the only fantasy series coming close to The Legend of Vox Machina is its own Prime Video sibling series, The Mighty Nein, which offers an ingeniously magical twist on the same formula. Between them, the two shows are Dungeons and Dragons' equivalent of Breaking Bad and Better Call Saul in the sense that it's almost impossible to decide which is better. We only know they're both brilliant.

That dual success grants Prime Video the #1 and #2 spots on any list of the best fantasy shows around right now.

The prevalence of successful fantasy shows on TV can only mean one thing: we're getting more of them. From Harry Potter to Artemis Fowl, Brandon Sanderson to Stephen King, Fourth Wing to Ravenloft, streaming stands on the precipice of a massive fantasy explosion.

And yet none of them are obvious candidates to knock The Legend of Vox Machina and The Mighty Nein off the top spots.

The likes of Artemis Fowl and The Dark Tower are notoriously tricky to adapt, while expectations from book fans could hamper shows based on Fourth Wing, Stormlight Archive, and other highly popular works. Ravenloft's Dungeons and Dragons roots immediately set lofty expectations thanks to Amazon's Critical Role shows, and HBO's Harry Potter faces a near-impossible challenge to win over its many critics.

That's not to say that one of streaming's upcoming fantasy projects can't blossom into brilliance and overtake both The Legend of Vox Machina and The Mighty Nein. But, on paper at least, there isn't a project in the pipeline that'll have Scanlan waking up at night nervously grabbing his lute.

36 Years Later, Hulk's Greatest Design Still Has No Equal

📅 Nov 08, 2026  |  Category: World  |  Read Source →

Almost 40 years after its Marvel debut, the greatest Hulk design of all time has yet to be bested, despite major competition both before and after. Here's why the design in question deserves its crown, and which other contenders come close.

Inspired by horror icons Frankenstein and Mr. Hyde, the Hulk was created by Stan Lee and Jack Kirby. Despite being one of the most iconic characters of all time, Hulk was originally very different - a grey-skinned jerk who spoke in sophisticated sentences and only came out at night.

Over the years, Hulk became the monosyllabic, emerald-skinned monster that Marvel fans know, though it took several of the most legendary creators in comic history to perfect Bruce Banner's other half.

The best Hulk design of all time is a hotly contested topic among fans of the Jade Giant, but we're handing the gold medal to Dale Keown, who drew The Incredible Hulk from 1990-1992 alongside acclaimed writer Peter David, with the two re-teaming for the non-canon Incredible Hulk: The End in 2002, which sees the character contend with a nuclear post-apocalypse.

Keown's Hulk is a barrel-chested behemoth with fists bigger than his head. His brow isn't just pronounced, it combines with a smaller, flatter nose and gaping mouth to create a hyper-expressive, highly distinct silhouette. The green skin is bright and luminous with a tonsure-like head of hair that looks like it didn't grow at the same rate as the rest of Bruce Banner's body.

So, what makes Keown our pick for the Hulk GOAT? It all comes down to one thing: Hulk's humanity. The best Hulk stories of all time understand that whatever Bruce Banner might think, the Hulk isn't a simple, singular expression of his rage. Hulk and Bruce are equally complex aspects of the same person - unique but deeply connected - and Keown communicates that better than any other artist.

There are a LOT of artists who have nailed Hulk's monstrous intensity and world-shattering rage. However, Keown's art is uniquely capable of showing Hulk laughing, glowering, grinning, wincing and roaring without losing the core of the character. Many of Hulk's earliest artists nail the sense of an impossible monster, but not one with a legitimate inner life.

The ability to depict different aspects of Hulk's personality was vital working alongside Peter David, who further splintered Bruce's psyche into the grey Joe Fixit, genius Professor Hulk and the brutal Maestro - the villain Bruce may one day become. These concepts have become the bedrock of Hulk's best modern stories - they were all good ideas, but it was Keown who ensured they were all 'Hulk.'

While we're holding Dale Keown up as creating the best Hulk design of all time, it's a close thing, given the wealth of talent who have worked on the character. And while you may not agree with our call, rest assured that there are many, many Hulk artists we still consider greats.

Hulk co-creator Jack Kirby drew Hulk with unbelievable menace, giving the character his heavy brow and tombstone teeth. Under Kirby, Hulk was a pure creature of the id - teeth bared and fists balled. Likewise, Herb Trimpe's Hulk is a howling monstrosity, reducing concrete to powder under his apish mitts and possessing a hunched, embattled physicality.

John Romita Sr.'s Hulk nails the concept of a monster that is still recognizably Bruce Banner, while Sal Buscema turned the character into a canvas for raw emotion. Despite a famously short run, it's worth noting that John Byrne accomplished the same sense of humanity as Keown, conveying a Hulk who is more than just rage.

In modern comics, Hulk has attracted some of the best artistic talent in comics. Adam Kubert's Hulk is an explosive mass of muscle that can't be contained by page or panel, Lee Weeks returns him to his Frankenstein-ian roots as a tragic homunculus, and John Romita Jr. captured a Hulk destroyed by grief and wrath, his humanity hanging on by a thread.

Bryan Hitch reinvented Hulk for the 2000s-era Ultimate Universe, turning him into a near-parodic wrecking ball of hate, lust and frustration. Daniel Acuña's work on Avengers: Twilight realized Bruce Banner's worst fears - the Hulk as an apocalyptic atrocity.

And while allegations that Joe Bennett hid antisemitic imagery in the background of Immortal Hulk can't be forgotten, he undeniably collaborated on the single greatest Hulk story of all time with writer Al Ewing, juxtaposing intense body horror and flying spittle with quiet, existential despair and righteous anger, bringing back Hulk's simian brow and bared teeth without abandoning the truth of a frightened child lashing out at an often deserving world.

While discussing Hulk's best comic designs, it would be silly to ignore his live-action appearances. Lou Ferrigno's snarling Hulk changed the franchise forever, acting as a near-unparalleled cultural touchstone. Ang Lee's Hulk embraced the imagery of a confused, superpowered toddler - dull-eyed and slathered in dirt - surpassing the pure rage of 2008's Incredible Hulk, at least in design.

However, the obvious winner is the MCU's Hulk, and for the same reasons as Dale Keown's art. Designed around the likeness of Bruce Banner actor Mark Ruffalo (who performs the Hulk's scenes using motion-capture technology), the most modern depiction of Hulk rages, but he also smirks, mourns, comprehends and fears.

This approach doesn't just make Hulk more interesting, it lets fans in on the vital lie that great Hulk stories deconstruct - that the Green Goliath is just a rage monster who lives inside Bruce Banner, rather than a vital aspect of his soul that's just as complicated and valid as the timid scientist.

Hulk's strength and size are essential to the character, but ultimately he also needs to be capable of emotional depth on par with his human side. The greatest piece of Hulk art of all time may or may not be by Dale Keown, but his design for the character encompassed everything the Hulk needs to be to tell the range of stories the character is capable of supporting.

Nuxeo API authentication is only the first permission decision

📅 Nov 08, 2026  |  Category: Technology  |  Read Source →

Nuxeo is a document platform with an API-oriented architecture. Its REST API can retrieve documents, inspect ACLs, run workflows, and expose custom endpoints. Authentication tells the server who is calling. The ACL attached to a document, folder, repository, or workflow determines what that identity can do.

On 2026-11-08, ZoomEye count-only observations returned 4 matches for app="Nuxeo", 186 for title="Nuxeo", and 28,973 for http.body="Nuxeo". The query used sub_type=all, page 1, and page size 1. The body count is far larger and can include documentation, examples, and unrelated pages. The application count is small, while the title count gives a broader product-level lead to validate.

Nuxeo documentation describes a default ACL managed through the document interface and permissions that can be granted or denied. It also describes an anonymous user that can be referenced when a repository administrator gives certain folders or documents public access. Anonymous access is therefore an explicit grant, not an accidental HTTP state.

The practical question is which anonymous grants still exist. A public document may be intentional, but a folder that was made public for a temporary campaign can become a durable information leak. The ACL enricher and @acl adapter can help an authorized operator inspect inherited and explicit access decisions.

Inventory each path. Confirm which headers are trusted, whether direct access to the application bypasses the proxy, and whether a test client can supply an identity header that the server accepts. A header that is safe only when stripped by the proxy is not an authentication control on a directly reachable listener.

List repositories and their public entry points. Identify top-level folders with broad read permissions, then inspect documents that are directly accessible through the REST path. Check inherited ACLs and any explicit deny or grant that changes the expected result.

Review principals, groups, and service accounts. An account used by a workflow may have access far beyond the worker's business purpose. Rotate credentials that are shared by multiple applications, and verify that removing a user from a group removes access to documents that the group granted.

Choose two accounts: one that should have access and one that should not. Request the same document by ID, path, and search endpoint. Then request the ACL and confirm that the effective decision matches the intended policy. Repeat after revoking a permission to ensure that cached authorization state does not preserve access longer than policy permits.

Use the REST API's error behavior as evidence, not as the whole test. A 404 can mean the document is hidden, while a 403 can reveal that it exists. Record the result without assuming that an authentication success means the object was authorized.

Nuxeo's API is designed to be programmable. The same flexibility makes an ACL inventory necessary. The product finding is useful only when paired with repository-level authorization evidence.
