Hill-Climbing Agent Quality with Agents CLI Evaluation

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

A live walkthrough of the Agents CLI eval loop, from a first run to regression tracking, model-backend experiments, and automated alerting

Building an agent that works on a demo is a different problem from building an agent that stays working across model upgrades, tool changes, and new conversation shapes. The first takes a weekend; the second takes a loop. A team writes test cases, runs them, grades them, reads what failed, changes the agent, and runs the cases again. If the score goes up, the change was good. If it goes down, revert. Over weeks of this, the agent inches toward the ceiling of what the model, tools, and prompt can do together. The quality-engineering name for this is hill-climbing.

The Agents CLI eval namespace was built around this loop. The commands are small and framework-agnostic: eval generate runs the agent against a dataset of cases, eval grade scores the generated traces, eval compare diffs two run results side by side, eval analyze clusters failures into themes, and eval optimize runs an automated hill-climbing pass on the agent's prompt.

A one-line system-prompt change propagated through three different cases in three different ways: greeting lost a point on tone, sf_weather lost two on tool usage, off_topic lost two on scope creep.

The lesson is that the summary number is misleading. Look only at the mean and you'd call gemini-2.5-flash as bad as the chef prompt. Look at the per-case breakdown and you'd call it a reasonable swap for most of the agent's workload, with one case (handling out-of-scope questions about recent events) exposing a real limitation. If the production distribution of user questions matches the first three cases more than the fourth, the swap is worth considering. If off_topic-style questions are common, it is not.

Two caveats on this experiment. First, model swaps interact with the prompt: a prompt tuned for a stronger model often leaks capability when ported to a weaker one, so the right comparison is "weaker model with a prompt tuned for it" versus "stronger model with its own tuned prompt." Second, the Vertex AI Eval Service calls a judge model to grade the traces, and the judge is held constant across the comparison. Changing the judge is a different experiment and should be done separately.

Agents CLI does not ship a scheduler, but the eval commands are designed to drop into standard infrastructure. The pattern we can use here is a cron job or Cloud Scheduler trigger that runs eval generate plus eval grade on a cadence and writes the results to a persistent location:

A nightly run against a stable regression dataset catches drift from model updates, data changes in the agent's tools, and dependencies that shift under the agent's feet. For a production agent, the scheduled run also captures the model vendor's quiet upgrades, which can move the agent's behavior without any change on our side. The dataset for the scheduled run is typically larger than the one used in the inner loop (dozens to hundreds of cases rather than a few), since it only runs once a day.

The scheduled run produces a result file every day, but a file nobody looks at is not an alert. The pattern here can be a wrapper script that compares each new run's mean against a baseline (the previous run, or a committed known-good) and exits non-zero when the drop exceeds a threshold. The non-zero exit is what triggers the alert from the surrounding scheduler.

For ADK projects, eval optimize runs an automated hill-climbing pass on the agent's prompt using the GEPA framework (not currently supported for the LangChain extension). The command takes a dataset and a target metric, proposes prompt variants, grades each one, keeps the variants that improve the metric, and iterates. The output is a set of candidate prompts ranked by their eval score, which a human then reviews and promotes to the agent definition.

Two things to understand about eval optimize. First, it is scoped to prompt optimization, not to arbitrary agent changes: the agent's tools, structure, and model stay fixed. Second, GEPA sometimes finds genuine improvements and sometimes finds prompt variants that score higher on the specific metric by overfitting to its wording. The reviewer is the control. For projects where the loop applies, the discipline is to run eval optimize on the regression dataset (where improvements are measurable) and to review the candidate prompts carefully before promotion.

A few patterns and anti-patterns from running this loop ourselves and watching teams do the same.

Lead with a small, representative dataset, not a comprehensive one. The temptation when starting an eval is to try to cover every edge case the agent will ever see. The result is a dataset that takes an hour to run and that nobody runs on a change. Four cases that run in under a minute, as above, exercise the main behaviors and get run on every change. A regression dataset of three hundred cases that runs for an hour becomes a release gate at best and shelfware at worst.

Snapshot result files, not scores. The score is a summary; the result file is the evidence. When a regression surfaces three weeks after a prompt change, having the full result JSON from before and after the change (not just the mean score) is what lets eval compare show the specific case that moved. The per-case breakdown in Step 4 above would not have been possible from scores alone.

Separate the dataset from its expectations. The dataset is the inputs. The eval config is the expectations. They evolve on different cadences: the dataset grows as new real-world cases surface in production, and the config evolves as the team's definition of "good" matures. Keeping them in separate files, both committed to version control, makes it clear which half changed when a score moves.

Treat summary metrics with suspicion. The model-swap experiment in Step 5 is the clearest example. The mean dropped by half a point, but the per-case breakdown showed the drop was concentrated in one case while the others held or improved. A team that only looked at the mean would have made the wrong call.

More evals do not automatically lead to more fixes. A recent controlled study we ran found that coding agents using agents-cli run four times as many evals as coding agents without it, but change the agent after an eval about as often as the baseline. The behavior gain comes from what the skills put into the build at the start, not from the inner iteration. Evals are necessary for quality, but the quality comes from acting on what the evals show.

Build Generative UI Apps with A2UI & CopilotKit Agents

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

Agent-User Interactions are now evolving from text exchanges to rich UIs. Until recently, most conversations looked like this:

User: "Find me a holiday package to Bali in March." Agent: (six packages in prose, each with dates, hotel, flights, price) User: "The five-night one with breakfast." Agent: "Here's the link. You can book it on the operator's site."

Agents could plan the trip, but everything came back as walls of text. They had no standard way to render a selectable list of packages, a map of the destinations, or a date picker to carry you through the rest of the booking, inside the conversation itself.

Generative UI is the layer that lets agents build interfaces at runtime, shaped by what each request needs - giving users a rich, interactive experience. Implementing that takes two pieces: a way to describe the UI and an agentic stack that connects your agent to your application and renders that UI.

Generative UI covers a spectrum of approaches, from using predefined higher order components, to enabling your AI agent to have the flexibility to decide how to build the UI.

At the controlled end, you build each component ahead of time, and the agent picks which one to render and with what data. It's brand-safe but it does not allow for deep customization and personalization based on the user’s intent. At the open end, the agent returns a raw UI program written in HTML, Javascript and/or Dart that renders inside a sandboxed iframe. That covers anything you did not plan for, at the cost of a surface that drifts from your design system and executes code a model wrote.

A2UI works through the entire spectrum. It participates in controlled generation with decision models like Typesafe’s Jev and also open-ended code generation that may output A2UI JSON messages. The declarative mode, where agents assemble pre-declared components and functions, is the most popular. A2UI is the framework-agnostic standard for declaring UI intent, so local or remote agents can generate your UI from your existing component catalog using a common language.

Frontend developers can now ship the building blocks once, and the agent composes them for each request.

The Basic Catalog ships 18 general-purpose primitives across layout, display, input, and containers. The agent can compose entirely different interfaces from the same 18 primitives, depending on what the request needs.

The Basic Catalog is deliberately sparse, so most production apps define their own custom catalog. A custom component can be anything your frontend already renders, including a live map the agent fills with coordinates while your renderer draws the route.

CopilotKit is built on AG-UI (Agent-User Interaction Protocol), which supports A2UI payload and provides Agent SDKs across many agentic backends.

Your agent emits A2UI operations. AG-UI carries them to the client as typed events. When the user takes any action, the values are sent back along the same stream.

A2UI works with any AG-UI compatible agent. Frameworks like Google ADK, LangChain, Mastra and Strands are all AG-UI compatible, so the setup is identical whichever one your agent runs on.

Setup comes down to two things: connecting your agent to CopilotKit, and defining which components the agent is allowed to use.

Any action the user takes on the interface (picking dates, choosing a flight, entering passenger details) travels back along the same stream, and the agent re-emits the surface from there using those values.

We Dropped Harbor for Large Images. A Traefik Default Was the Cause.

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 4 • Originally published at amalzacharia.com • AI-assisted

I stopped pushing large images to Harbor because the pushes kept failing. The cause was a default in Traefik, which I had adopted only because ingress-nginx was retired.

It took me a while to see that, and the reason is the useful part. Every metric I had said the system was healthy.

The cluster is new and runs on bare metal. Only HTTP and HTTPS need to be reachable from outside. Everything else is consumed inside the private network or the cluster, where eBGP handles routing fine.

For the public side I used Cloudflare Tunnel. A tunnel needs no public IP on the cluster. Cilium's L2 announcements were still beta and send all inbound traffic for an address to a single node, so I didn't want to build the edge on them. The tunnel also removed two chores. I didn't have to set up authenticated origin pulls, and I didn't have to maintain a firewall that blocks every IP outside Cloudflare's ranges, because the origin only makes outbound connections.

The request path is Cloudflare's edge, the tunnel, Traefik, then the service. Traefik was my ingress because ingress-nginx, the previous default, was retired in March 2026. I knew nginx's timeouts well. I knew almost nothing about Traefik's.

My images lived on GHCR. GitHub's docs say fine-grained tokens don't cover Packages, and I found no native way to issue a pull credential limited to part of an account's images. Harbor has project-level RBAC and robot accounts that stay inside one project, so I ran Harbor in the cluster.

CI pushed built images to it. Small images went through. Large ones timed out, and not every time. I tried to work around it from the client side, and the workarounds were flaky. In the end I stopped sending anything over 100 MB through Harbor.

I put the failures down to something in front of Harbor, most likely Cloudflare. Prometheus had nothing to contradict that. It had nothing to confirm it either.

A separate project needed object storage. It builds kernel and root filesystem images for microVMs, each a few gigabytes. They lived in a hosting provider's object store, and the provider had no region near the nodes that run the microVMs. Whenever the artifact cache expired or a new artifact shipped, every node pulled it from another region over a congested public route.

So I moved storage into the cluster: an S3-compatible store behind the same tunnel and the same Traefik. The first publish was a huge multipart upload, and I split it into 100 MB parts.

Splitting the upload into 100 MB parts didn't stop the failures. The cloudflared pod's CPU and memory sat flat. Nothing was overloaded, so something configured was cutting the connections.

The public internet doesn't guarantee throughput, which matches the pattern. A part that hit a slow stretch took longer than the others, and only those parts failed.

The cluster was new, so observability was already in place. Prometheus and Loki had told me nothing useful. Tempo was the missing piece. I pointed Traefik's tracing at it, turned on Cloudflare's trace export to the same place, and retried the upload.

Cloudflare saw the origin answer 504 after about 60.2 seconds. Traefik's own span ended at exactly 60.0 seconds. A network fault doesn't end at a round number.

Traefik's entrypoint readTimeout defaults to 60 seconds, and the docs say it covers reading the entire request, including the body. A multipart part is one request. Any part whose body took longer than a minute to arrive was cut with a 504, whatever the client was configured to tolerate.

That explained everything I had seen. The failures were intermittent because the speed of the public route varied, and client-side workarounds did nothing because the limit lived on the server. Prometheus showed nothing because a timeout adds no load.

nginx behaves differently. Its client_body_timeout limits the gap between two successive reads of the body, so a slow but steady upload survives it. Traefik's limit covers the whole request. I had no reason to know that difference until I migrated.

I retried the huge upload and it went through cleanly. Then I retried Harbor, and the large pushes that used to fail succeeded.

An intermittent failure that ends at a round number is a timeout until something proves otherwise. Metrics measure load, and a timeout adds none, so the dashboards can stay green the whole time.

When a deprecation forces you onto a new component, read its timeout defaults before you send your largest request through it. Put traces in before you need them. The hop I couldn't see was the one at fault.

I dropped Harbor for large images on a wrong explanation, and I only found the right one because a different project forced me to look.

How Oregon State turned a raw athlete into a starting linebacker

CORVALLIS — Two years ago, Jarrel Comer was a freshman at Tallahassee Community College and had not played competitive football since middle school. Now he's a starting outside linebacker at Oregon State.

Comer played basketball at Eastside High School in Gainesville, Florida, but began college as a regular student. He looked for opportunities to play sports again and football became the opportunity at Citrus College in California.

He boarded a plane for the first time to take a cross-country flight to play football for the first time in more than four years.

"I was willing to take that chance to get to where I am today," Comer said.

He had 58 tackles (8.5 for loss), including six sacks at the California junior college and got on the radar of linebackers coach Cort Dennison, then at Idaho. Dennison kept pursuing Comer at OSU, where he signed in January and arrived during the spring.

At 6-foot-4 and 245 pounds, Comer was dominating in junior college from his athleticism alone. He didn't know the finer points of playing football. Hand placement, setting the edge in the run game and pass coverage were not in his repertoire. Comer was there to pin his ears back and attack the quarterback, regardless of the down and distance.

"They didn't ask much of me," Comer said. "They told me just do what I do, use my athleticism, get to the quarterback."

What Comer lacks in experience, he makes up for in ability. He consistently ranks among OSU's fastest players in practice, which was invaluable to a team seeking more pass rush.

"His athleticism is off the charts," defensive coordinator Mike MacIntyre said. "We see him grow leaps and bounds. Playing a lot more (against Montana), he will grow leaps and bounds going into this Saturday because now he's seen it, it slows down, he understands the different things."

BigBear.ai vs. Nebius: Which AI Stock Is the Better Buy for 2027?

One of these AI stocks is shrinking and losing money, while the other is growing at triple digits and just turned profitable.

As the artificial intelligence (AI) race intensifies, investors are looking beyond the biggest names for hidden opportunities. Deciding between BigBear.ai (BBAI -1.94%) and Nebius Group (NBIS +7.25%) requires weighing government contracts against cloud infrastructure.

BigBear.ai focuses on decision-intelligence software for high-stakes defense environments. Nebius builds the actual full-stack infrastructure needed to train and deploy these complex models. While both companies operate in the fast-moving AI sector, their business models, financial health, and customer bases offer investors starkly different paths.

BigBear.ai provides specialized decision-intelligence and autonomy software tailored for government and commercial sectors. It provides biometric and data analysis solutions, with a major concentration of contracts adding a layer of risk.

On a trailing-12-month (TTM) basis through the June quarter, revenue reached nearly $142 million, which represents a decline of approximately 1.5% compared to the prior year.

The company reported a net loss of close to $180 million. This performance indicates that expenses significantly exceeded total sales.

As of its June 2026 balance sheet, the current ratio is approximately 4.9x, measuring the ability to cover short-term debts with current assets. The debt-to-equity ratio was 0, as the company carries no debt.

TTM free cash flow, which is cash from operations minus capital expenditures, was negative $73 million, indicating the business consumes more cash than it generates.

Nebius Group positions itself as an AI cloud company, building the full-stack infrastructure required for complex machine learning tasks. Its platform supports AI builders across healthcare and financial services by offering tools for model training and deployment. The company operates a global footprint with data centers and roughly 400 AI engineers to maintain its competitive position.

As of the June quarter, TTM revenue reached nearly $1.4 billion, representing a significant 444% year-over-year increase. Net income improved to $62 million, up from under $10 million for the full year 2025. This performance shows a swing to profitability following significant net losses in previous years, driven by high demand for cloud services.

Based on its June 2026 balance sheet, the current ratio is approximately 4.0x, while the debt-to-equity ratio is roughly 1.0x. The company's total debt was approximately $8.6 billion, with an additional $1.5 billion in lease liabilities. This was partially offset by $8 billion of cash and equivalents.

TTM free cash flow was negative $5.9 billion, reflecting the capital-intensive nature of the company's AI infrastructure. Note that stock-based compensation accounted for roughly 21.6% of operating cash flow, inflating reported cash generation because it is a non-cash expense.

BigBear.ai faces significant risks from revenue concentration, as a large portion of its business depends on a limited number of government contracts. These agreements are subject to budgetary fluctuations and may be terminated at any time for convenience.

Nebius is funding massive capital spending needs. Heavy capital investment for data centers has resulted in negative free cash flow, and a slowdown in AI demand remains the primary risk.

BigBear.ai appears cheaper based on sales over the past twelve months, while Nebius is the only one with a positive forward P/E using future earnings estimates.

I would buy Nebius over BigBear right now. BigBear has a multi-year history of flat revenue. It reported $146 million in revenue in 2021, and $128 million in 2025. It has reported a net loss across that period. The company has to compete for government contracts, while Nebius has seen its revenue explode due to a shortage of data center capacity and high demand.

Nebius is seeing immediate demand for its infrastructure as soon as it is brought online. Additionally, Nebius benefits from pricing power, with recent bids for compute capacity fetching higher prices than before.

Analysts expect BigBear to continue reporting losses over the next few years, while expecting Nebius to continue growing earnings over the long term as it brings more capacity online.

The risk for Nebius is that the stock trades at high multiples of sales and earnings. A lot of growth is priced in, so anything that stalls the AI build-out could hurt the stock. The stock has already fallen 38% in the last month over concerns about AI spending.

Still, Nebius has a scarce asset that is in high demand, and that scarcity is being validated by explosive revenue growth and improving profitability. That's the stock I would rather hold for 2027 and beyond.

Google offers weak response to accusations it would hold Search hostage if schools restrict AI tools

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

Google LLC just faced a barrage of criticism after the company warned that if schools restricted their students from using its artificial intelligence tools, the same students wouldn’t be able to use Search.

The fallout came after the company announced a slew of new products for classrooms. Teachers and schools were told that the new AI tools would come with features that will allow for limitations or complete blocks of the features, but if teachers or schools should take that route, students would not be able to use Google Search. Some media described it as rather cunning behavior from the tech giant.

“After listening to schools, teachers, leading researchers, and policymakers, we are now updating our approach to controls for Gemini, Gemini Notebook, Gemini in Classroom, and Google Search,” Google said in a blog post. “Access to these products will be entirely off for K-12 student accounts until school administrators explicitly turn them on.”

A New York Times article followed the announcement and explained that where schools have banned the use of AI or if they limit AI in the classroom, the students would not have access to Search. With Google’s suit of products being a mainstay in classrooms all over the U.S., the backlash was imminent.

“Google is trying to use its monopoly power to force AI into our public schools,” New York City Mayor Zohran Mamdani wrote on X. “No corporation should have the power to dictate how we teach our children. Our public schools exist to serve students, not to grow the profit margins of Big Tech.”

Sen. Bernie Sanders from Vermont was equally chastising, writing on X that, “Google is threatening schools,” and using what amounts to, “extortion.” Lina Khan, former chair of the U.S. Federal Trade Commission, was similarly unimpressed, writing that Google was trying to, “coerce schools into adopting AI”.

Google was quick to respond. In a post on X, the company said its new policy is about giving schools more control over how students use AI. Gemini chatbot, Gemini Notebook, the company explained, will be turned off by default, but “schools are in control.”

“We are also updating Search for schools to make it better for learning,” Google added. “Specifically, AI Mode and AI Overviews will offer step-by-step guided learning through problems, so that students don’t get quick answers to schoolwork.” The company explained that it was aware of the dangers of students embracing the “AI shortcut” and effectively not engaging their brains.

In what seemed like a sleight of hand or exercise in obfuscation, Google seemed to ignore the basis of the criticism regarding Search not being available when AI functions were turned off. Given the company has found itself under the gun many times in recent years for its sometimes-underhand business tactics, and in light of studies showing overuse of technology can have a harmful impact on children, the response seemed tepid at best.

Applied Compute operates a cloud platform that developers use to train large language models and perform inference. Additionally, it has a team of machine learning researchers that can lend customers a hand with their projects. The group takes on tasks such as creating quality evaluations for newly developed models.

The software stack that AI researchers use to train LLMs usually comprises two main components. One creates multiple copies of the model, assigns a different task to each one and turns the results into training data. The other component uses that training data to refine the LLM’s weights. The two components usually run synchronously, which means that each one has to wait for the other to complete its work before launching.

Applied Compute’s platform uses a more efficient training approach called asynchronous RL. It enables a training stack’s data generation and weight adjustment components to run at the same time, which speeds up LLM development. Additionally, the platform supports a second optimization method called self-distillation. It removes the need for teacher models, specialized neural networks that researchers use to supervise LLM training runs.

A built-in AI assistant automates repetitive aspects of customers’ work. It can, for example, summarize what new skills an LLM learned during a training run. Uncovering that information usually requires researchers to review lengthy reasoning logs.

Applied Computing’s platform also lends itself to running inference workloads. An autoscaling engine automatically adjusts the amount of hardware allocated to a model based on user traffic. A so-called online RL feature uses the prompts that the LLM receives to periodically fine-tune its weights, which keeps it aligned with customer requirements.

Applied Computing offers its training and inference features alongside a model router called Shift-1. It enables coding agents to send each user request to the LLM that can fulfill it in the most cost-efficient manner. Furthermore, it can split complex tasks among multiple LLMs.

Applied Computing disclosed in its funding announcement that its annualized recurring revenue has topped $100 million. The company, which launched less than 18 months ago, counts Microsoft Corp., DoorDash Inc. and other major tech firms as customers. It will use the newly raised capital to grow its market presence and buy more infrastructure.

“Training, inference, and routing are the first pieces of a much larger stack,” Applied Compute founders Rhythm Garg, Yash Patil and Linden Li wrote in a blog post. “We’re building the AI infrastructure every company will need to fully own their intelligence, from the models themselves to the systems that run, monitor, and secure them.”

The conversation ultimately highlights how designers increasingly need to understand the larger systems that determine how—and whether—their ideas can make a difference.

Unfortunately, color options have been reduced to just Midnight and Starlight. The price has also increased: the new iPad mini costs $200 more, starting at $699 for the 128GB model. We'll let you decide if it's worth it; for now, let's look at the changes Apple has made to its compact tablet offering this year.

The big iPad mini upgrade this time is the OLED panel. That makes it the only other iPad in Apple's lineup with an OLED display aside from the iPad Pro. It's roughly the same resolution as last time, but can get much brighter at up to 1,200 nits of peak HDR brightness. OLED also brings other benefits: the new iPad mini is the same height and nearly the same width, but is thinner at 5.4mm and lighter at 255 grams — likely thanks to the thinner OLED panel. In comparison, the A17 Pro iPad mini maxes out at 500 nits of SDR brightness, weighs 293 grams and is almost an entire millimeter thicker at 6.3mm.

The new iPad mini also features a slightly larger 8.5-inch display, owing to the bezels that are now 24 percent thinner. The only major letdown is the lack of ProMotion. Plenty of users on X have understandably expressed disappointment about Apple sticking with a 60Hz display on a $700 product in 2026. Despite its nearly identical design, the new iPad mini is Apple's first water-resistant iPad. One of the ways it has achieved an IP67 rating is by replacing the speaker grilles with its new Acoustic Display system. This involves tweeters placed between the glass and aluminum body, with woofers firing through the display. The result, apparently, is punchier bass, clearer treble and more volume. It's similar to the Huawei P30 Pro's acoustic display, though that particular setup was largely designed to replace the earpiece speaker for phone calls rather than deliver a full stereo speaker experience like the iPad mini.

"Investors seem to have a significant dose of skepticism about whether the final outcome is going to be quite as favorable to Democrats as the polling suggests," Marcus told CNBC, noting that the firm shares the view that the "polling is likely overstating Democratic strength."

JPMorgan sees a blue wave knocking the S&P 500 by about a half percent on Wednesday.

On the other hand, if Republicans end up retaining both chambers of Congress, that could spur a rally, said Sameer Samana, head of global equities and real assets at the Wells Fargo Investment Institute.

"The reason stocks often perform well in November during midterms is because [the S&P 500] typically is weak INTO the elections. We have the opposite setup this year," Krinsky wrote last week. “Biomarker testing does play a critical role here, and it is important for people to be aware of the potential benefits,” Socinski said. “It may help change the course of a person’s treatment journey.”

Gosselaar hopes that greater awareness of biomarker testing can help people facing a cancer diagnosis feel more informed about their treatment options.

“A lot of the time, when a loved one or someone who has been diagnosed with cancer [it can] feel like your world is in a tailspin,” he said. “I wanted to get the word out for anyone who’s going through a cancer diagnosis, or a caretaker, to know that biomarker testing is an option, because even though two cancers are similar, their tumors can act very differently and biomarker testing may help the medical expert with more personalized treatment.”

As part of the campaign, Gosselaar took part in a commercial, something he hadn’t done since before his days on “Saved by the Bell.”

“This was the first time that I actually had to be on set and not be a character; I had to be me talking about this very serious issue,” he said.

While it was a challenging experience, he said it was also fulfilling.

“I enjoyed the process, and to be able to use my platform to be able to spread the word; it means a lot to me,” he said. “I’m very selective of the things that I want to attach myself to, and this seemed like the right fit.”

He particularly enjoyed recreating Zack Morris’s signature “timeout” gesture from “Saved by the Bell,” which allowed his character to freeze time and speak directly to the camera.

“Using something from the past that was such a symbolic gesture to so many people of my generation that are now my age and possibly going through [cancer] or knowing someone who’s going through [cancer to] direct them to [this campaign], means a lot,” he said.

Beyond his efforts to raise awareness about cancer biomarker testing, Gosselaar is equally focused on taking care of his own health.

Getting quality sleep is one of his top priorities. He sleeps on a high-tech mattress that monitors sleep stages, heart rate, heart rate variability, and respiratory rate. He also uses a biometric health and fitness tracker, prioritizes healthy eating, and uses saunas and red light therapy.

“We do everything that we possibly can, but I’m less about longevity and more about just living a healthy lifestyle,” Gosselaar said. “I want to continue doing the things that I’ve done since I was a child…without feeling held back by my health.”

As he embraces his 50s, he said he’d like to live a long life for his children and future grandchildren. He started taking his health seriously in his 40s after undergoing shoulder surgery.

“[It] really made me realize [that] all the damage I had done in my 20s and 30s sort of adds up later in life, and that’s probably something that I would tell the younger me… to preserve a little bit more and take [an] approach that recovery is just as important as the workout because I did not use my recovery very well; it was not a priority for me,” said Gosselaar.

He also makes time for himself every day. He said doing so makes him a better person and more able to care for his wife and four children.

“[It’s] something that I believe in; that I need to do something for myself before I can do something for someone else. Or if I do something for someone else, then I have to equalize that by doing something for me,” he said.

Daily physical activity also helps support his mental well-being.

“I need to do something where I challenge myself, and it could be as simple as a walk. It could be as simple as just getting outside and lifting something heavy [or] taking bags of groceries and taking the long way into your house,” Gosselaar said.

“Like challenging yourself with picking up things, you know, taking backpacks from the car from your kids and seeing if you can carry three in one hand…or going into the gym and spending an hour in the gym, or 30 minutes, or just moving.”

When he’s in the sauna, he works on breathing and clearing his thoughts.

“Some people need to meditate, some people need to talk to somebody. I encourage all of that because I think all of that helps,” he said.

“I’ve done them all. I’ve done the cold plunging, I’ve done all that stuff…some of it works, and some of it doesn’t; it’s whatever you believe in. So I just encourage people to stay healthy and move, get outside, and help other people.”
