How to fix "MCP: Unsupported protocol version"

📅 Nov 20, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 20 • Originally published at runheed.com

Returned with HTTP 400 (code -32000) by HTTP MCP servers built on @modelcontextprotocol/sdk 1.x when a request's MCP-Protocol-Version header names a version the SDK does not know. SDK 1.32.2, the last 1.x release, supports 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05 and 2024-10-07. MCP 2026-07-28 is the first stateless revision: it drops the initialize handshake, so a client speaking it sends the version on every request, and the Python SDK 2.x lists it as its latest version.

If clients still connect, there is nothing to fix today: a client that supports both eras treats a 400 without a modern error body as a legacy server and falls back to initialize, which your 1.x server answers. To serve clients that speak only 2026-07-28, move the server to the v2 package (@modelcontextprotocol/server), which supports both. Do not fake the new protocol's UnsupportedProtocolVersionError (-32022) from a 1.x server: that error tells a client the server is modern, so it stops falling back.
