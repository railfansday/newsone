Rig of Troy: A Suspicious Recovery Script Hidden Inside Roblox Toolbox Models

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

An investigation into suspicious R6 models, hidden GUIs, remote code loading, and a possible social engineering attack.

R6 models and animations in the Roblox Toolbox.

Everything seemed normal until I inspected one of the models more closely.

Inside the character's Right Arm, I found something unexpected: a script called Runtime.lua, accompanied by a complex hierarchy of objects that seemed completely unrelated to the model's intended purpose.

At first, I thought it was just an unusually complicated animation system.

Further investigation revealed suspicious scripts, hidden interface components, and code designed to convince developers to execute an external command.

I decided to call this investigation Operation Rig of Troy.

After finding the first suspicious model, I started examining other assets from the Toolbox.

Surprisingly, I encountered very similar structures in multiple models, sometimes published by different creators.

The most interesting detail was the location of the GUI.

In the models I examined, suspicious interface components repeatedly appeared under MovementElevateAction.

Why would an R6 animation need an entire interface system hidden inside a character's arm?

There might be legitimate explanations for unusual object hierarchies, but the repeated structure justified further investigation.

I examined the source code without intentionally executing the suspicious recovery command.

This code only proceeds while running in Roblox Studio.

The script then locates a ScreenGui named InputBinding inside the MovementElevateAction hierarchy.

After finding the interface, it clones the stored objects into the player's PlayerGui.

The script also contains a fingerprinting mechanism based on object attributes and names, along with checks that can stop the installation under certain conditions.

This confirmed that the script was installing an interface, not simply controlling an animation.

However, this script alone did not prove that a malicious remote module was being executed.

The next important discovery was a client-side script named WindowDriver.lua.

This script was responsible for building and displaying the interface.

One particularly interesting section waited until the script had detected sufficient user activity before presenting the notification.

This made the interface appear during an active Studio testing session.

The script also assembled its text from attributes stored in the GUI rather than keeping all messages directly in the source code.

Several attributes were named Row22, Row23, and so on.

These attributes contained fragments of a Lua command.

The suspicious command appeared designed to retrieve a module identifier from an external endpoint and load the corresponding module.

Even more interestingly, the interface used two sets of attributes:

Rows 22–27: The actual text placed inside the selectable text field.

Rows 80–85: The text rendered in the syntax-highlighted preview.

The script made the underlying text transparent and displayed a separately rendered version above it.

This design could potentially display different text from what the user copies. However, I did not establish that the two versions were different in the examined sample.

The confirmed concern was already significant: a model was presenting instructions that encouraged the developer to execute externally sourced code in Roblox Studio.

This is consistent with a social engineering technique, rather than an ordinary animation dependency.

This is where the distinction between evidence and assumptions matters.

However, I did not identify or reverse engineer the final remotely loaded module.

Therefore, I cannot conclusively state what the final payload would do.

It might have been intended to install a backdoor, but confirming that requires additional evidence.

I also cannot establish who originally created the scripts or whether every model containing the same structure was distributed by the same actor.

The investigation illustrates why Roblox Toolbox assets should not automatically be trusted.

A free model may contain much more than its visible parts.

Importantly, do not execute unknown malware simply to see what happens. Static inspection can already reveal significant information.

Instead, I found a suspicious runtime system, unusual GUI structures, a hidden window driver, and a potential social engineering mechanism involving remote code execution.

I did not prove the existence of a functioning backdoor payload, but I documented a concerning method of persuading developers to execute untrusted code.

For me, this investigation was also an introduction to practical cybersecurity research: examining source code, comparing artifacts, identifying suspicious behavior, and separating facts from hypotheses.

And everything started with a character's arm.

We Dropped Harbor for Large Images. A Traefik Default Was the Cause.

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

Posted on Nov 4 • Originally published at amalzacharia.com • AI-assisted

I stopped pushing large images to Harbor because the pushes kept failing. The cause was a default in Traefik, which I had adopted only because ingress-nginx was retired.

It took me a while to see that, and the reason is the useful part. Every metric I had said the system was healthy.

The cluster is new and runs on bare metal. Only HTTP and HTTPS need to be reachable from outside. Everything else is consumed inside the private network or the cluster, where eBGP handles routing fine.

For the public side I used Cloudflare Tunnel. A tunnel needs no public IP on the cluster. Cilium's L2 announcements were still beta and send all inbound traffic for an address to a single node, so I didn't want to build the edge on them. The tunnel also removed two chores. I didn't have to set up authenticated origin pulls, and I didn't have to maintain a firewall that blocks every IP outside Cloudflare's ranges, because the origin only makes outbound connections.

The request path is Cloudflare's edge, the tunnel, Traefik, then the service. Traefik was my ingress because ingress-nginx, the previous default, was retired in March 2026. I knew nginx's timeouts well. I knew almost nothing about Traefik's.

My images lived on GHCR. GitHub's docs say fine-grained tokens don't cover Packages, and I found no native way to issue a pull credential limited to part of an account's images. Harbor has project-level RBAC and robot accounts that stay inside one project, so I ran Harbor in the cluster.

CI pushed built images to it. Small images went through. Large ones timed out, and not every time. I tried to work around it from the client side, and the workarounds were flaky. In the end I stopped sending anything over 100 MB through Harbor.

I put the failures down to something in front of Harbor, most likely Cloudflare. Prometheus had nothing to contradict that. It had nothing to confirm it either.

A separate project needed object storage. It builds kernel and root filesystem images for microVMs, each a few gigabytes. They lived in a hosting provider's object store, and the provider had no region near the nodes that run the microVMs. Whenever the artifact cache expired or a new artifact shipped, every node pulled it from another region over a congested public route.

So I moved storage into the cluster: an S3-compatible store behind the same tunnel and the same Traefik. The first publish was a huge multipart upload, and I split it into 100 MB parts.

Splitting the upload into 100 MB parts didn't stop the failures. The cloudflared pod's CPU and memory sat flat. Nothing was overloaded, so something configured was cutting the connections.

The public internet doesn't guarantee throughput, which matches the pattern. A part that hit a slow stretch took longer than the others, and only those parts failed.

The cluster was new, so observability was already in place. Prometheus and Loki had told me nothing useful. Tempo was the missing piece. I pointed Traefik's tracing at it, turned on Cloudflare's trace export to the same place, and retried the upload.

Cloudflare saw the origin answer 504 after about 60.2 seconds. Traefik's own span ended at exactly 60.0 seconds. A network fault doesn't end at a round number.

Traefik's entrypoint readTimeout defaults to 60 seconds, and the docs say it covers reading the entire request, including the body. A multipart part is one request. Any part whose body took longer than a minute to arrive was cut with a 504, whatever the client was configured to tolerate.

That explained everything I had seen. The failures were intermittent because the speed of the public route varied, and client-side workarounds did nothing because the limit lived on the server. Prometheus showed nothing because a timeout adds no load.

nginx behaves differently. Its client_body_timeout limits the gap between two successive reads of the body, so a slow but steady upload survives it. Traefik's limit covers the whole request. I had no reason to know that difference until I migrated.

I retried the huge upload and it went through cleanly. Then I retried Harbor, and the large pushes that used to fail succeeded.

An intermittent failure that ends at a round number is a timeout until something proves otherwise. Metrics measure load, and a timeout adds none, so the dashboards can stay green the whole time.

When a deprecation forces you onto a new component, read its timeout defaults before you send your largest request through it. Put traces in before you need them. The hop I couldn't see was the one at fault.

I dropped Harbor for large images on a wrong explanation, and I only found the right one because a different project forced me to look.

A red test can mean three very different things: the application broke, the network blinked, or the site showed a bot challenge. Most tools report all three as "failed", so teams learn to rerun reds instead of reading them.

Nexus Studio, by Verdict System LLC, gives every run one of 14 verdicts. Here is one run of seven tests and what each one said:

SECURE: passed on its own. FLAKY: failed, then a retry passed it. Nothing was fixed. BREACHED: the application broke. A real finding. TIMEOUT: never answered in time. CRASHED: the browser died. BLOCKED: a 403, a 429 or a bot challenge. UNREACHABLE: the host could not be reached. Only BREACHED is a bug report. The other failures say the environment or the harness is at fault, and a retry never turns a defect into a green run.

Every failure leaves a folder of evidence: a forensic report you can read without the Studio, a screenshot, console and network data, a video for a real defect, and an optional SHA-256 chain of custody. An Executive Report turns the history into a go, caution or no-go call.

Bashpole Location Guide For Phantom Blade Zero

📅 Nov 04, 2026  |  Category: Health  |  Read Source →

In Phantom Blade Zero, Phantom Edges are among the most useful tools in Soul's repertoire. While they have their uses as weapons, some of them, like the Bashpole, are great for getting around and uncovering hidden secrets throughout the world.

Even though the Bashpole is required to access some spots in the game's early locations, you can't get it until much, much later. Luckily, being able to fast travel around the map makes going back to these spots easier, so it's easy to wonder just how to get this Phantom Edge. Here's where to get the Bashpole in Phantom Blade Zero.

To get the Bashpole, you'll need to get into the Mandate Encampment. This comes later than it might initially seem, since when Soul arrives in the Village of Lu, he mentions that the road splits: one way leads to the village, and the other leads to the Mandate Encampment.

This makes it seem like you can go to the Mandate Encampment first, but this isn't the case. Instead, you have to get through the whole Village of Lu, then go through Pangzhen until you beat Gu Wanyue, The Wailing Wraith. After you beat her, you can enter the Well of Wei Sanchuan, where you'll find the key to the Mandate Encampment.

Travel to the gate, go through and make your way through the Mandate Encampment until you reach the bell titled Beneath the Watchtower. Next to it is a gate sealed with a large chain, which you can break with the Cleave Axe. On the other side, you'll meet Wan Jun, The Coppermaul.

If you've got decision paralysis about which Phantom Edges to use, look no further.

Once you open the gate and face the behemoth that is Wan Jun, you'll have to protect yourself first and foremost. He deals less damage than his size might suggest, but luckily moves just as slowly as you might think. He's also clumsy, which opens the door for strikes that can whittle down his health and guard.

Most of his attacks will involve the Bashpole and can be parried or dodged. Because he's so slow, dodging is easier than with some other bosses, letting you build as much distance as you need. He can't close the gap quickly, so you have time to react.

Don't be afraid to get in a few quick strikes while he collects himself. He's slow and remains open for a while.

Watch out for double strikes with the Bashpole, as those are his fastest attacks. Unlike some bosses with heavy armor or shields like Wu Xuan, The Fallen General, you can break his guard with attacks, so you don't have to parry or dodge to break it. Stay patient as he goes through his attacks, and use the openings to strike when he falls over or stumbles.

Using the Bashpole is pretty simple, given that it's really just a giant metal melon on a stick. When equipped, you can hold your Phantom Edge button (R2 on PS5) to swing the Bashpole around your head three times, then slam it down onto the ground. If you release the button early, you'll slam it down before completing three rotations.

For traversal, you don't need to equip the Bashpole, just like the other traversal Phantom Edges. When you're near a weak floor made out of wooden boards, you can press R2 to slam the Bashpole into the ground, causing Soul to fall through into the level below.

The pause before the action: how Sakupa's confirmation step works

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

A quick disclosure first: I am not Sakupa's developer. I came across this MCP server while looking into how AI agents publish websites, and this post only organizes facts from its official site and official manual. This is not a hands-on review.

Sakupa is an MCP server that lets an AI agent publish and operate a static website without account registration. This time I want to focus on one design choice: before anything is published or changed, the agent has to stop and show you what it is about to do.

The pattern, as described in the official manual, is simple: analyze first, preview the change, confirm, and only then execute. The agent does not go straight from your request to a live change. It prepares the change, shows it, and waits for confirmation.

This matters more than it sounds. When you ask an AI to change a website, the most common failure is not a dramatic one. It is a small one: the wrong date, the wrong page, a wording change you did not mean. A preview step catches those before they go live, when fixing them is still cheap.

It is tempting to read a confirmation step as friction. But in Sakupa's case, the pause does three quiet jobs:

The same idea shows up elsewhere in Sakupa. Payments go through a Stripe-hosted page rather than through the server itself. Credentials stay on the user's own machine. The design keeps the sensitive parts in places where they can be checked.

A confirmation step does not decide whether the change is a good idea. It only shows you what the change is. The content — the hours, the menu, the announcement — is still yours to decide. And Sakupa only handles static sites, so anything needing a database or login functionality is out of scope. A contact form is available as the first app in its catalog, with its own page-side contract and a verification code for the notification address.

When an AI agent can act on your behalf, the interesting question is not how fast it acts. It is where it stops and asks. Sakupa's answer is: before every publish and every change, with a preview you can actually read. If you are curious, the 30-day free preview is a reasonable way to try that flow once, on a small change, before committing to a plan that starts at ¥200 per month per site.

In 2026, leading Layer 1/Layer 2 ecosystems alongside enterprise fraud engines (Cloudflare Turnstile, Arkose Labs) have deployed Behavioral Biometric Telemetry.

Even if your IP is a pristine static residential proxy and your Canvas/WebGL fingerprint is randomized, heuristic algorithms analyze the physical telemetry of your interactions. When 50 different browser profiles perform daily check-ins with mechanically identical click patterns, those profiles are clustered and flagged as a Sybil Cluster in seconds.

Standard tools like OP Auto Clicker, GS Auto Clicker, or unthrottled Python pyautogui scripts trigger bot detection via three fundamental mechanical signatures:

Humans cannot click the exact same pixel (X₀, Y₀) repeatedly. Physiological tremors in the fingers and wrist cause subtle variations of ±1 to ±3 pixels.

Basic clickers pass the exact same integer coordinates on every event call. When an analytics heatmap reveals 100 clicks on (450, 720) with 0 variance, you are instantly categorized as non-human.

A script configured to click every 500ms will fire events at t₀, t₀ + 500ms, t₀ + 1000ms. Heuristic detectors run Fast Fourier Transforms (FFT) or standard deviation checks on timestamp deltas (Δt). A standard deviation near zero (σ ≈ 0) is mathematical proof of software automation.

How does Oahu get to an economically resilient, 100% clean energy future?

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

Oahu is a unique place. It’s the home of one of the largest clean tech incubators in the world, Elemental Impact, for a reason. Exorbitantly high electricity rates combined with ample natural resources make it an incredible laboratory to bring clean tech solutions to market. Rapid investment for WWII created a grid that was dependent on foreign oil. Path dependency (the idea that “what you know” becomes what you continue to do) hampered innovation and resulted in the creation of infrastructure (multiple power plants across multiple islands) that still, today, burns diesel fuel as large generators, to produce electricity for the island. Throw in a dependence on imported fuels that must come at least 3,000 miles to arrive, being the strategic hub for the entire Pacific theater of the U.S. military, one of the wildest weather years and hurricane seasons the island chain has ever seen AND the state’s economic dependency on tourism dollars, high cost of living, and low wages, and and wow – you’ve got yourself a puzzle and a half to solve in order to get the place to a sustainable future.

Analyst Mike Barnard loves a challenge, so he set forth to put together a roadmap to help Oahu get to 100% clean energy, which helps recirculate money in the state, lower costs, create jobs and foster economic resiliency.

Recently I gave a talk at Hawaii Tech Week in which I summarized this report, added in my own experience running an energy efficiency service that has now greened more than 20,000 homes and is saving Hawaii residents over $10 million a year on their utility bills, and then compiled the new and coming technologies that can help the island get off fossil fuels.

Mike’s report did something very important. The state’s own reporting and strategy looks at the big picture, a very difficult mountain to climb. Mike looked at that mountain and removed some of the false summits and unachievable viewpoints, resulting in a much more achievable and strategic pathway. What he did was eliminate the things we simply cannot fix right now – long distance flights, maritime bunkering, and military fuels – and tackled the problem of Oahu’s actual energy consumption for its residents. The result was that it was achievable, and there are technologies right now today that can be deployed in what he refers to as a “no regret stack” first and foremost.

I combined that with my approach, which was to showcase the economic resilience it creates. Case in point, an LED bulb saves so much money on Oahu that it pays for itself in 18 days. Every day after that, it is like change plinking in a piggy bank for the person who put it in. That builds economic resiliency for those who need it most. From LEDs to e-bikes to heat pump water heaters to balcony solar – it all adds up – fast payback periods, and financial independence.

Mike comes back to the things we simply can’t fix right now and argues that the tech will come – but for the duration of the 2020s and into the 2030s, we should be installing parking lot solar canopies, agrivoltaics, heat pump water heaters, and more.

AMD beats expectations as agentic AI sparks its data center revenue growth engines

📅 Nov 04, 2026  |  Category: Technology  |  Read Source →

Shares of the chipmaker Advanced Micro Devices Inc. were up more than 5% in late trading today after it delivered solid third-quarter earnings and revenue today, with data center sales almost doubling from a year ago.

The company reported earnings before certain costs such as stock compensation of $2.09 per share, easily beating Wall Street’s forecast of $1.95 per share. Revenue for the period jumped 45% from a year earlier to $13.38 billion, ahead of the $13.09 billion analyst consensus estimate. All told, the company’s net income for the quarter came to $3.47 billion, up 77% from the previous year when it posted a profit of just $1.96 billion.

The star performer in the quarter was AMD’s data center business unit, which accounted for 64% of its overall revenue, up from just 47% one year ago. After spending years trying to compete with Nvidia Corp.’s graphics processing units for artificial intelligence market share, the company’s traditional central processing units or CPUs are suddenly back in vogue thanks to the emergence of agentic AI applications such as Meta Platforms Inc.’s Muse. Autonomous AI agents can run much more efficiently on CPUs than they can on GPUs, boosting demand for the chips.

Looking ahead, AMD expects its server revenue to double year-over-year in fiscal 2027, with AI growth likely to accelerate even faster than the company projected just three months ago. “Adoption is just starting and we expect demand to grow sharply as agents are deployed more broadly and take on more complex work,” said AMD Chief Executive Lisa Su (pictured) on a conference call with analysts.

AMD’s data center story isn’t all about CPUs, though. The company also sells GPUs, including bundles of them shipped inside data center-ready rack-scale systems called Helios, and that system’s popularity is growing fast. Su said Anthropic PBC, OpenAI Group PBC, Microsoft Corp., Oracle Corp. and Meta are all using AMD Helios systems in their data centers. Last week, Meta said its first Helion racks are already up and running as it revealed that AMD invested $1 billion in its latest equity offering.

The chipmaker has also committed to a $5 billion investment in Anthropic, which last week revealed the long-awaited prospectus for its upcoming initial public offering.

AMD delivered its latest earnings report just days after its rival Intel Corp. did the same. Intel also posted strong data center revenue growth, but its stock fell more than 30% on Friday due to weak guidance and concerns over its ability to meet demand for its products. But Su said AMD had no such problems. She made a high-profile visit to Taiwan last month where she held meetings with Taiwan Semiconductor Manufacturing Co. and a number of supply chain partners, and said after the trip that the company plans to substantially increase its supply in the coming year. “We have worked across our supply chain to secure the wafers, substrates, advanced packaging, memory and other key components needed to support much higher growth next year,” Su added.

AMD’s results will go some way towards reassuring investors who have become increasingly nervous about the direction of the AI industry and whether or not the hundreds of billions of dollars being spent on it each year is actually going to generate a return on their investments, said Emarketer analyst Jacob Bourne. “The results are a test of AMD’s own performance and the broader AI trade, and its data center and revenue beats will encourage investors after the recent semiconductor selloff,” he added.

While AMD is far from immune to the recent volatility that has afflicted AI-related stocks, its future still looks increasingly rosy for now. “Demand for AI computing is not going to fall off a cliff, and AMD has the competitive products and major customer relationships to capitalize on that demand,” Bourne said.

Strength in the data center unit is helping AMD to ride out difficulties in its traditional market for personal computers, which is the reason for Intel’s poor outlook. During the second quarter, global PC shipments were down 4% from a year earlier, with buyers dissuaded by the rising cost of components such as memory chips, according to data from Counterpoint Research. Along with Intel, AMD is a leading manufacturer of the x86 CPUs that power most of the world’s computers and laptops. The company reports PC chip revenue within a segment that also includes its chips for games consoles, and that unit saw its revenue decline 8% from a year earlier to $3.7 billion. Gaming revenue was down 40% from the previous year.

For the current quarter, AMD is targeting revenue of around $17 billion at the midpoint of its guidance range, ahead of the Street’s $16.2 billion consensus estimate. The company also sees its gross margins coming in at 55%, just below the Street’s forecast of 55.3%.

AMD was busy on the acquisition front during the quarter. In September it revealed it’s going to buy World Labs Inc. for $8.2 billion in an all-stock deal. The San Francisco-based AI lab was founded by the AI industry luminary Fei-Fei Li, and has developed world models that can simulate 3D environments to support the training of intelligent robots and other physical AI applications.

The company also acquired a startup called Taalas Inc. that makes specialized model-specific integrated circuits, which are essentially chips that can be customized to run a specific AI model more efficiently. That acquisition should help to boost AMD’s position in AI inference. AMD also invested in the AI image generation model maker Stability AI Ltd., which raised $76 million in funding in August.
